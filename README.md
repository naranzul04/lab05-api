| Горим | Файл | Assertions executed | Assertions failed | Exit code | Тайлбар |

| **PASS** | `results/newman-pass.txt` | **23** | **0** | **0** | Бүх тест амжилттай давсан (CI quality gate нээлттэй) |
| **FAIL** | `results/newman-fail.txt` | 23 | ≥ 1 | **1** | Зориуд өөрчилсөн oracle унаж, exit code 1 буцаасан |
| **DOWN** | `results/newman-down.txt` | 0 | 0 | **1** | Сервер унтарсан үед `ECONNREFUSED` холболтын алдаа гарсан |

* **Интерфейсийн алдаа vs Oracle-ийн алдаа:** `ECONNREFUSED` нь сервер унтарсан эсвэл порт нээлттэй бишээс үүдэлтэй **транспорт/холболтын (интерфейсийн) алдаа** бөгөөд HTTP хариу ирээгүй тул assertion ажиллаагүй; харин oracle-ийн алдаа нь серверээс ирсэн бодит хариу хүлээгдэж буй шаардлагатай зөрөхөд үүсдэг.
* **Локал API ба Нийтийн API харьцуулалт:** Локал `POST /registrations` API дээр тест бүрийг бие даасан байлгахын тулд `PUT` setup хүсэлтүүд болон төлөвийн хослолуудыг бэлтгэх шаардлагатай байсан бол `GET https://jsonplaceholder.typicode.com/users` нь төлөв өөрчилдөггүй тул нэмэлт setup-гүйгээр шууд бүтэц ба өгөгдлийг шалгахад хялбар байв.

## 4. Дүгнэлт

Тест дизайны 5 алхмаас **сонголтуудыг ялгаж, эквивалент ангиудад хуваах болон давхар алдааны хослолуудыг тодорхойлох** нь хамгийн их бодол шаардсан хэсэг байв. Учир нь оюутны төлөв, бүртгэл, хичээлийн бүртгэл, урьдач нөхцөл болон оролтын JSON форматын хувьд олон боломжит төлөв үүсдэг ч бүгд зэрэг бодит нөхцөл болж чаддаггүй. Жишээ нь, идэвхгүй оюутан эсвэл байхгүй оюутан дээр урьдач нөхцөлийн `missing` жагсаалт буцах эсэхийг шалгахад сервер эхлээд оюутны оршин байдал болон идэвхтэй төлөвийг шалгаж байгаа нь бодит туршилтаар батлагдсан. Мөн нэг хүсэлтэд олон нөхцөл давхцах үед серверийн шалгах дарааллаас хамаарч аль алдаа түрүүлж буцахыг урьдчилан таамаглалгүй туршилтаар нягтлах шаардлагатай байсан. Тест бүр өөрийн `PUT` setup-тай байснаар in-memory санах ойд `registrationID` хуримтлагдах эсвэл өмнөх тестийн өгөгдөл нөлөөлөх эрсдэлээс сэргийлж чадсан. Серверийн үндсэн логик зааврын дагуу зөв ажиллаж байсан тул шинэ программ кодын согог илрээгүй ч давхар алдааны тэргүүлэх дараалал болон тестүүдийн хамааралгүй байдлыг баталгаажуулах нь чухал байв. Мөн CI/CD орчинд exit code `1` гарах нь автомат pipeline-ийг зогсоох чанарын хаалт (`quality gate`) болдгийг `FAIL` болон `DOWN` горимуудаар практикт харлаа.
